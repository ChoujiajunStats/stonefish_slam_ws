# M1 与 M2 的运行边界

M2 的源码修改前快照与 M1-v4 独立镜像均保留。当前工作区含 M2 新模块，
所以源码文件哈希已不再与历史 M1-v4 冻结清单相等。原 M1 正式冻结入口应拒绝
对这份新源码声称仍是 m1-v4；历史 54 个通过结果不作任何改写。

原 observation-only 和 M1 配置仍分别由 schema 1/2 处理。M2 独立 schema 3，
同一镜像内新增传感器语义仅在显式场景属性开启。M0/M1 使用 M2 镜像复测时，
manifest 会额外保存 M2 补丁锁与实际依赖清单，不把新增补丁隐去。

M2 使用 OpenVINS 状态输出；其诊断运动使用明确隔离的 M1 真值反馈控制器。
因此 M2 估计曲线通过与 M1 控制回归通过是两类证据，不代表“估计状态闭环控制”
已经通过。当前无导航、无实机接入。

M2 验收中的故障运动停止由测试程序显式 DISARM 触发，并从原生末端反馈核验
接收设定值归零时间和 RPM/推力衰减。这个检查不会被写成“估计健康自动控制
电机”的通过结论；估计状态到控制器的健康门尚未接入。

同一 M2 镜像下的 M1 回归执行原病例与原断言，报告为选定范围回归；不会把
M1-v4 历史 54 次 PASS 写成本轮又完成了 54 次。
