# Porth 全范围建图采集计划（2026-09-24）

先核验几何，再运行真实推进器驱动的数据采集。此前 2.4 m 短路线的
SLAM 成功不代表整洞覆盖。此次主通道几何弧长约 186 m，另有侧支洞。

本轮新增显式 `porth_survey` 采集配置：已知碰撞网格只用于离线制定路线
和独立安全/覆盖评价，控制反馈明确为 `PRIVILEGED_DEBUG`；OpenVINS
和 RTAB-Map 的输入仍是双目、IMU 和估计里程计。普通启动默认 DISARMED，
显式 `--arm` 才执行路线。沿用真实自由刚体、八推进器、原末端 watchdog、
物理步长、相机和 DDS，不实现自主避障。新增独立 survey 镜像的光学补丁
只允许 LIGHT 与八推进器共存，旧镜像不覆盖。

修改范围：`simulations/` 离线路线/场景照明，`navigation/` 纯路径跟随，
`benchmark/` 采集与覆盖评价，`app/` 显式配置和组装，`guard/` 显式诊断
反馈选择，`config/`、`test/`、`docs/`。不改历史验收记录或上游动力学。

按顺序执行：

1. 对主通道及可通行支路制定往返路线，记录尺度、净空、排除端部。
2. 新增有限时、独占 Guard 授权的采集器；先做短程照明/跟随检查。
3. 固定路线和参数后实际运行长程采集，保存状态 bag、原始 SLAM 数据库、
   过程日志、真实图像。新任务数据预算 25 GB，不删除旧数据。
4. 重读数据库导出点云，以原始完整视觉网格的面积采样作为覆盖率分母，
   报告全范围/遗漏区域、误差与可视证据。不能以补洞网格代替观测覆盖。

运行完成、路线覆盖、表面重建覆盖分别判定；遇到真实故障保留失败并修复。
没有达到全表面覆盖时明确报告部分重建。

用户追加要求：每次运行展示两个图形窗口；参考 OceanSim 的光学实现，
提供可调青绿色水下雾感。核验纹理加载、锁定原生水体模型，再用真实图像
验证追踪能力。不能把更换光学参数后的结果拼接成同版验收。

## 当前返航约定（2026-09-24）

用户确认：先将保留朝向的全程采集跑通，再修改返航方式。
v3 与后续 v4 保持冻结的朝向规则，
返程允许负机体 vx（倒车），不在运行中修改路线或参数。
真正掉头后向前返航留待当前采集与重建评价完成后另立版本，先验证掉头时的
净空、图像连续性与 SLAM 跟踪；不能把本轮结果算作掉头返航通过。
v3 在 555.8 m 因 SLAM 处理超时失败；v4 保留同一路线和朝向，已完成全程。

两种运动都可以作为 SLAM 实验：保留朝向提供较相近的重复视角，掉头返航
增加视角变化、转向跟踪和反向地点识别的难度。本项目对后续全洞覆盖更倾向
掉头版本，这是针对前向双目和随车灯的工程选择，不是通用 SLAM 标准。
有限视场下的反向视角识别可参考 [SPOT（ICRA 2024）](https://umautobots.github.io/spot)；
真实洞穴采集中的多环路与重复观测见作者的
[GoPro VI-SLAM 数据集说明](https://joshi-bharat.github.io/projects/gopro/)。
后续比较固定场景、光学与算法，分别报告跟踪中断、轨迹误差、接受的回环、
表面覆盖和数据量/耗时；不能只比较回环数量，也不能以倒车版通过推断反向
视角识别已通过。
