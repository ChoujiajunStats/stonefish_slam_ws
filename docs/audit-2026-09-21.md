# 首次审计：2026-09-21

审计发生在实现前。输入为根目录 `underwater-stack-architecture.md`，
当时除此文件外无代码、Git 历史或构建产物。

## 结论

方案适合渐进实施。先实现 M0，暂不生成后续算法包。宿主 Ubuntu 24.04、
Python 3.12.3、RTX 5090（约 32 GB 显存）、驱动 580.178.04、内存约 62 GiB，
磁盘空闲约 549 GiB。Docker 29.8.1 / Compose v5.5.1 客户端存在；
当前用户不在 docker 组，访问 `/var/run/docker.sock` 返回 permission denied，
`sudo -n` 需要密码。不能据此确认 daemon、GPU runtime 或镜像可运行。
没有安装项目所需的宿主 ROS/CMake，符合容器隔离原则。

## 发现及处理

| 项目 | 源码证据 | M0 处理 |
|---|---|---|
| 默认启动混入 ArduSub | BlueROV `launch/bluerov2_sim.py` | 直接启动 Stonefish，禁止桥接 |
| 默认 tank 有 Seabed | `scenarios/bluerov2_tank.scn` | 独立空水域模板，只合入机器人 |
| 缺少真实 `/clock` 权威 | ROS `ROS2SimulationManager.cpp` | 固定提交补丁：物理步时间、steady pacing |
| 消息使用临时 ROS 时钟 | `ROS2Interface.cpp` 和 manager | 补丁统一使用当前物理步时间 |
| 双目投影平移为 0 | `GenerateCameraMsgPrototypes` | 共享几何配置，右相机 P[3] = -fx × 0.145 |
| 场景 baseline 字段不等于已实现 | Stonefish parser 不读取 camera baseline | 不依赖此属性，运行时检查投影与几何 |
| NED/FRD 与公共 ENU/FLU 不同 | Odometry 与 IMU 源码 | 数值、姿态、协方差完整转换 |
| IMU 为运动学加速度 | `IMU::InternalUpdate` | 标明不含人为添加重力，不宣称可直接供 VIO |
| Steel 材料引用未在 tank 定义 | BlueROV 机器人 + tank | 空水域显式定义 Steel |
| 节点 this 被独立 shared_ptr 接管 | `stonefish_simulator.cpp` | 补丁改为不拥有节点的借用指针 |
| 原设计示例 controller 已启用 | `controller_profile: body_velocity_4d` | M0 限定 `disabled`，未知/未来能力拒绝 |
| 复现锁不完整 | 三个提交无法锁定 apt/GPU | 固定基础镜像 digest，记录构建实际软件清单 |

所有补丁是待编译候选，源码核查和补丁可应用不等于运行验证。
渲染图像以最近物理步时间打戳，双目采样同步精度留待 M2 实测。
空水域缺乏视觉纹理，不能用作 VIO/导航性能场景。

## 首阶段交付范围

五个实际 ROS 包：`uw_app`、`uw_robot`、`uw_simulations`、`uw_ui`、
`uw_benchmark`。`interfaces/` 先维护契约；后续包按需求出现。
提供容器构建、固定上游和补丁、派生场景、观察 launch、严格运行配置、
唯一输出目录、有限时长探测、版本/退出原因/传感器证据与 RViz 配置。
M0 不接收任何推进器命令，无自动解锁，无 PID、OpenVINS 或任务执行。
